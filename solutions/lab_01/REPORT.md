2. Фрагменты полученных результатов
   
`ast task_1.py`
```bash

         value=Call(

```

## Задание 2. Имена, объекты и сравнение

```python
a = 1000
b = a
c = int("1000")

print("Типы:", type(a), type(b), type(c))
print("Идентификаторы:", id(a), id(b), id(c))
print("a == b:", a == b)
print("a is b:", a is b)
print("a == c:", a == c)
print("a is c:", a is c)
```

0. Прогноз:
   - `print("a == b:", a == b)` - True
   - `print("a is b:", a is b)` - True
   - `print("a == c:", a == c)` - True
   - `print("a is c:", a is c)` - True
1. Связи между именами и объектами:
   - `a` → объект №1: int, значение 1000
   - `b`→ объект №1: тот же самый объект
   - `c` → объект №2: int, значение 1000
2. Разница между равенством значений и идентичностью объектов заключается в том, что `==` сравнивает значения,  
а `is` проверяет, один ли это объект 
3. Изменил значение `c` на `None` и добавил проверку того, что `c` обозначает объект `None`:  
`print("c is None:",c is None)`
4.
```python
first = "python"
second = "py" + "thon"
print(first == second)
print(first is second)
```
   `print(first == second)` вывел `True`, так как значения переменных одинаковы
   `print(first is second)` вернул `True`, потому что при компиляции CPython "заранее"  
   посчитал данное выражение, использовав при присваивании общую константу.

5. Правило: применять `==`, когда нужно сравнивать значение объектов, а - `is` - для проверки, являются ли  
объекты идентичными.

### Ответы на коктрольные вопросы

1. Инструкция `b = a` не создает копию объекта
2. `type()` - возвращает тип объекта, `id()` - возвращает идентификатор объекта
3. `None` принято сравнивать с помощью `is`, а числа и строки — с помощью `==`, потому что  
в Python - особенный. Он существует в единственном экземпляре. Числа и строки как правило  
интересуют по значению. Объектами они могут являться разными.

## Задание 3. Числовые типы, операции и преобразования

### Эксперимент A. `int` и арифметические операторы

`x = 17` и `y = 5`:

- `x + y` = 22 `int`;
- `x - y` = 12 `int`;
- `x * y` = 85 `int`;
- `x / y` = 3.4 `float`;
- `x // y` = 3 `int`;
- `x % y` = 2 `int`;
- `x ** y` = 1419857 `int`.

`/` и `//` возвращают разные значения и могут возвращать результаты разных типов,  
потому что `/` выполняет обычное деление и для двух `int` возвращает `float`,   
а `//` выполняет деление с округлением вниз. Тип результата `//` зависит от типов операндов.

### Эксперимент B. Большие целые числа

```python
2 ** 1000
```

Челые числа __Python__ отличаются от целых чисел фиксированной разрядности  
во многих других языках тем, что размер `int` в __Python__ увеличивается   
по мере необходимости и фактически ограничен доступной памятью.

### Эксперимент C. `float`

```python
result = 0.1 + 0.2
```

- `result` - 0.30000000000000004;
- `result == 0.3` - False;
- `result - 0.3` - 5.551115123125783e-17;  
Так произошло, потому что "в конечном счете" числа храняться в двоичной  
системе счисления, а `0.1` и `0.2` невозможно представить в виде конечной двоичной дроби.
- `math.isclose(result, 0.3)` - True.  
`math.isclose(a, b)` - равны ли приблизительно `a` и `b`?

### Эксперимент D. `bool`, `complex` и явное преобразование типов

1. 
   - `int("42")` - 42
   - `float("3.14")` - 3.14
   - `str(2026)` - 2026
   - `bool(0)` - False
   - `bool(-1)` - True
   - `bool("")` - False
   - `bool("False")` - True
   - `complex(2, -3)` - (2-3j)
2. `bool(x)` - использует `x` как условие, и определяет будет ли оно считаться истинным
3. `bool("False")` дает истинное значение, потому что для строк `bool()` возращает `True`, когда строка не пустая.
4. Вывод действительной и мнимой части комплекского числа:
```python
print(complex(2, -3).real)
print(complex(2, -3).imag)
```
### Ответы на контрольные вопросы: 

1. Результат обычного деления двух объектов `int` имеет тип `float` для однозначности результата деления.  
Очень часто числа не делятся нацело.
2. Отличие преобразования `int("42")` от `int(42.9)` в том, что в первом случае `int()` сделает явное преоброзвание,  
только если в строке записано целое число. Во втором случае `int()` отбросит дробную часть и совершит преобразование.
3. `0` и `""` из эксперимента D являются falsy.

    - `coefficient` - `complex`
    - `modulus_squared` - `float`
    - `has_runs` - `bool`

2. Разбор арифметической строки:

    ```python
    total_minutes = total_seconds / 60
    ```

    - `60` - целочисленный литерал
    - `total_minutes` и `total_seconds` - имена
    - `/` - оператор деления
    - `=` - знак присваивания
    - вызовов функций в этой строке нет

    Сначала вычисляется выражение `total_seconds / 60`, затем имя `total_minutes`  
    связывается с результатом этого выражения. Результат имеет тип `float`.

3. Путь выполнения программы:  
    исходный файл `task_5.py` → разбор исходного текста → AST → компиляция в байткод → выполнение виртуальной машиной CPython.  
    AST описывает структуру программы. При компиляции получается байткод,  
    команды которого выполняет виртуальная машина CPython.

4. Результат `input()` необходимо явно преобразовывать перед арифметическими вычислениями,  
    потому что `input()` возвращает объект `str`. Например, при вводе числа `8`  
    возвращается строка `"8"`. Количество запусков преобразуется с помощью `int()`,  
    а длительность запуска, действительная и мнимая части коэффициента - с помощью `float()`.  
    Имя исследователя и название эксперимента остаются строками.

### Ответ на контрольный вопрос:

После повторного присваивания имя связывается с результатом нового выражения справа.  
Само присваивание не изменяет прежний объект. Тип объекта, с которым теперь связано имя,  
может отличаться от предыдущего.

Например:

```python
runs = 8
runs = 10
```

После второй инструкции имя `runs` связано с объектом `int` со значением `10`.  
Объект со значением `8` от этого не превращается в объект со значением `10`.  
Ранее вычисленные результаты, например `total_seconds`, автоматически не пересчитываются.
